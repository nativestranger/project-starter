# Project Starter

A small Markdown starter for projects run by people and agents. It assumes no product, business model, or technology stack.

## Files

| File | Purpose |
| --- | --- |
| [AGENTS.md](AGENTS.md) | Agent instructions, concise writing, and working habits. |
| [PROJECT.md](PROJECT.md) | Current objective, status, priorities, decisions, and next three tasks. |
| [DESIGN.md](DESIGN.md) | Problem, intended users, approach, scope, and enduring rationale. |
| [VALIDATION.md](VALIDATION.md) | Success criteria, assumptions, experiments, and evidence. |

## Start a project

1. Copy these five files into the new project's root directory.
2. Replace this introduction with a short project description. Keep the file map.
3. Define the first objective and constraints in `PROJECT.md`.
4. Fill the other notes only when useful. Empty sections do not block work.

Keep one active plan in `PROJECT.md`. Link to design and evidence instead of repeating them. Add separate distribution, outreach, or technical documents only when the work needs them.

## Use with Codex

Keep the exact filename `AGENTS.md` at the project root. Start a new Codex task with that project as its working directory. Codex loads applicable instructions automatically. Closer instruction files and explicit task instructions can change the result. A sibling project's file does not apply here.

After changing instructions, start a new task or ask an existing task to reread the file. To check, ask: "Which instruction files apply, and what writing style will you use?"

See [OpenAI's instruction guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md). These files guide agent behavior; they do not run background work.
